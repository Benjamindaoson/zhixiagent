## 上游 `dev` 新增能力

- **交互式分析应用**：在分析工作区运行受沙箱约束的 HTML/React 应用，涉及前端预览、运行桥接、数据查询和后端沙箱。
- **工作流与定时执行**：新增工作流实例、调度和运行状态管理，涉及 Agent、会话持久化与界面。
- **语义模型与更多连接器**：增加 Power BI、Cube 等数据源与语义模型处理。
- **模型连接与多语言**：扩展模型连接流程和语言资源；对当前已配置的兼容 API 是否有收益，需要单独验证。

这些属于开发分支中的能力，不能仅凭分支存在就写成知析 AI 已支持的功能。`main...dev` 差异涉及约 598 个文件，其中前端约 191 个、Python 约 159 个。以本地定制提交与 `dev` 模拟合并，出现 11 个冲突文件，集中在 `App.tsx`、`DataFormulator.tsx`、`DataThread.tsx`、模型/依赖配置和翻译资源。因此不直接整体覆盖现有工作区。

## 第一项集成：可操作的分析仪表盘

知析 AI 已加入交互式分析的首个可用切片：在现有工作区中选择已加载的表格、字段、筛选值、图表类型与汇总方式，复用 `/api/tables/sample-table` 读取最多 1,000 行并在前端计算指标。此切片不等于完整移植 `dev` 的应用生成、沙箱执行和运行桥接；当前无需修改 Python 后端。样本指标会在界面标明读取行数。

实现与验收记录见 `openspec/changes/interactive-analysis-dashboard/`；下一步若需要生成可编辑的小型应用，应单独评估上游沙箱及数据访问契约，再按相同门槛集成。

## 逐项集成的验收边界

1. 为选定能力写明用户流程与依赖；保留首页、五个示例、左侧画布与右侧对话、会话保存、品牌和流式回答显示。
2. 在隔离分支移植该能力及其必要的前后端契约，不把其他 `dev` 重构顺带并入。
3. 使用项目本地依赖环境运行相关测试、TypeScript 检查和生产构建；启动本地服务，浏览器验证首页、原有示例及新能力。
4. 只有通过上述检查，才将该能力并入知析 AI `main` 并更新 README。外部模型、数据库和定时服务若未实际接通，明确标注验证边界。
